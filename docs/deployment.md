# QUBIT — deployment runbook (MVP1 Phase D)

Target: a reachable Next.js 15 app backed by **managed Postgres 17** with **Row-Level
Security enforced in the database**. This is what "onboard real people" requires beyond
the local `qubit_clickup` dev DB.

## 0. Prerequisites
- Node 20 LTS+, `pnpm`.
- A managed Postgres 17 instance and an **app DB role that is NOT superuser and NOT
  `BYPASSRLS`** — RLS is the tenant boundary; a superuser role silently bypasses it.
- A host for the Next.js server (container/PaaS) and a domain with TLS.

## 1. Secrets
Copy `.env.production.example` into your host's secret manager and fill every value:

| Var | Purpose |
|---|---|
| `DATABASE_URL` | Managed Postgres, pooled, `sslmode=require`, non-superuser role. |
| `AUTH_SECRET` | NextAuth signing — `openssl rand -base64 32`. |
| `AUTH_URL` | Public origin, e.g. `https://qubit.example.com`. |
| `MFA_ENCRYPTION_KEY` | Encrypts TOTP secrets at rest. Rotating it invalidates all enrolled MFA. |
| `ANTHROPIC_API_KEY` | Q copilot. Optional — Q degrades to deterministic reports without it. |
| `AZURE_AD_*` | Optional SSO. |

## 2. Schema + RLS
Migrations embed the RLS policies (every tenant table gets `tenant_isolation_*`), so
applying them provisions the schema **and** the security policies:

```bash
pnpm install --frozen-lockfile
pnpm prisma migrate deploy      # schema + RLS (idempotent)
pnpm prisma generate
```

Verify RLS is live before onboarding anyone:

```sql
-- every tenant table should show rowsecurity = t AND forcerowsecurity = t
SELECT relname, relrowsecurity, relforcerowsecurity
FROM pg_class WHERE relkind='r'
  AND relname IN ('user','project','team','project_member','ai_call_log','audit_log')
ORDER BY relname;
```

> **Do NOT run `pnpm prisma:seed` in production** — the seed creates synthetic demo users
> with a well-known password. Use the bootstrap script instead.

## 3. Bootstrap the tenant + first admin
Creates just the Riverbank tenant row and one `SystemAdmin` (no demo data). Idempotent.

```bash
ADMIN_EMAIL=joyce.okore@riverbank.solutions ADMIN_NAME="Joyce Okore" \
  pnpm tsx scripts/bootstrap-tenant.ts --tenant riverbank
```

It prints a one-time temp password for a **new** admin (nothing if the admin already
exists). Distribute securely; the admin resets it and enables MFA at `/settings/mfa`.

## 4. Build + run
```bash
pnpm build
pnpm start        # or your process manager / container CMD
```

Quality gates before shipping a build: `pnpm typecheck && pnpm lint && pnpm test`.

## 5. Onboard real data
Follow [`docs/onboarding/README.md`](./onboarding/README.md): fill the CSV templates,
dry-run until warning-free, `--execute`, hand off temp credentials, enable MFA, QA in the
UI, then delete `import/import-report.json`.

## 6. Post-deploy verification
- Sign in as the bootstrap admin over HTTPS.
- **Admin → Users**: only real users; MFA enabled on privileged accounts.
- Create a throwaway project, confirm **Ask Q** returns a grounded report, then remove it.
- Confirm `ANTHROPIC_API_KEY` works (report footer says "Generated by Claude", not
  "AI key not configured") — or leave unset to run deterministic reports.
- Cross-tenant check (if a second tenant exists): its data is invisible to Riverbank
  users (RLS test `tests/rls/*` codifies this).

## Operational notes
- **Backups + PITR** on the managed DB; test a restore.
- **Migrations**: run `prisma migrate deploy` on each release; migrations are additive and
  ship reversible `down.sql`.
- **Secrets rotation**: `AUTH_SECRET` rotation logs users out; `MFA_ENCRYPTION_KEY`
  rotation forces MFA re-enrollment — plan a window.
- **No PII in logs**: `AiCallLog` stores metrics only; keep app logs free of tenant PII.
